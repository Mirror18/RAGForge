# 项目章程

## 1. 项目目的

RAGForge 用一个真实 Obsidian 仓库作为首批数据源，系统性学习和验证商业级知识库产品的建设方法。衡量成功的标准不是“能回答问题”，而是系统是否具备可解释、可评估、可维护、可审计、可部署和可演进的工程能力。

## 2. 项目目标

1. 构建可部署的企业内部知识助手 MVP。
2. 建立从数据接入、解析、分块、索引、检索、重排到回答生成的可版本化流水线。
3. 同时支持本地 Ollama 与经空间授权的 OpenAI-compatible 云端模型。
4. 建立产品、研发、测试、安全、运维、评估和开源合规的完整项目资产。
5. 形成可以复用于其他企业 AI 项目的实践、ADR、模板和复盘。

## 3. 非目标

- 首版不做公有 SaaS、多租户计费或跨租户资源共享。
- 首版不做文档级 ACL；权限边界止于知识空间。
- 不把本地 9B 模型承诺为 20 并发生产 SLA。
- 不做任意代码执行、数据库写入或开放互联网 Agent。
- 不追求一次覆盖所有文件格式和知识库连接器。
- 不通过换皮或长期 Fork 某个成熟开源产品代替架构学习。

## 4. 成功指标

### 4.1 产品结果

- 用户可创建空间、配置成员、接入数据源、观察索引状态并进行带引用问答。
- 运维人员可定位一次回答使用的空间、索引、流水线、检索、提示词和模型版本。
- 空间未授权云端出境时，任何内容都不会被发送给云端提供商。

### 4.2 质量门槛

- 120 条以上版本化评估用例。
- `Recall@10 >= 0.90`，`MRR@10 >= 0.75`。
- 引用准确率、忠实度和应拒答准确率均 `>= 0.90`。
- 跨空间泄漏测试必须为 0 例。
- 100 万可检索 child chunks 下，检索服务端 `p95 < 1.5s`。
- 非 AI API 在目标负载下 `p95 < 300ms`。

所有指标必须注明数据集、硬件、并发、模型、索引和配置版本，不能只保留一个孤立数字。

## 5. 目标规模和容量假设

| 项目 | MVP 设计目标 |
|---|---:|
| 注册用户 | 200 |
| 云端/Mock 推理链并发 | 20 |
| 文档 | 100,000 |
| 可检索 child chunks | 1,000,000 |
| 对话保留 | 90 天 |
| 原始调试提示词保留 | 7 天 |
| 审计日志建议保留 | 365 天 |

本地 `qwen3.5:9b` 只承担功能验收和单用户体验，不用于证明上述并发推理容量。

## 6. 利益相关者视角

| 角色 | 主要诉求 |
|---|---|
| 平台管理员 | 用户、全局提供商、系统健康、安全和审计 |
| 空间管理员 | 成员、数据源、模型出境策略、空间配置 |
| 编辑者 | 接入和维护文档、观察解析和索引质量 |
| 浏览者 | 检索、问答、引用核验和反馈 |
| 开发者 | 稳定契约、本地可复现环境、可测试架构 |
| 运维/安全 | 指标、日志、Trace、告警、备份、恢复和事故证据 |

## 7. 治理机制

- 范围变化：修改 PRD、路线图、风险表和追溯矩阵。
- 架构变化：新增或替代 ADR；不直接重写已接受 ADR 的历史结论。
- RAG 行为变化：保存离线评估的基线、候选和差异报告。
- 第三方复用：先过许可证闸门，再引入依赖或源码。
- 阶段结束：在 `docs/08-records/retrospectives/` 形成复盘；项目稳定后再摘录到 Obsidian。

## 8. 当前开放问题

以下问题不会阻断骨架建设，但应在对应阶段关闭：

1. 首个云端 OpenAI-compatible 提供商和预算上限。
2. OCR 首选实现与中英文扫描件验收集。
3. S3-compatible 实现的开发/生产选型。
4. 对外开放 REST API 时 service token 的轮换周期和细粒度 scope。
5. 是否在 MVP 后支持 OIDC/LDAP，以及迁移策略。
