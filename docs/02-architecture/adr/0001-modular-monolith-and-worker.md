# ADR-0001：模块化单体与独立摄取 Worker

- Status: Accepted
- Date: 2026-08-12

## Context

项目需要完整商业工程能力，但当前规模为 200 用户、20 条云/Mock 推理链并发。在线对话与批量解析的资源形态和失败模型不同，直接做全微服务会放大部署、契约和分布式事务成本。

## Decision

业务主系统采用 Java 模块化单体；摄取 Worker 独立部署；OCR/rerank 使用窄职责 Python AI Runtime。模块通过显式 application ports 和事件交互，用架构测试防止边界腐化。

## Consequences

- 本地调试、事务和重构成本较低。
- 摄取可独立扩容和隔离失败。
- 必须认真治理模块边界，否则会退化成大泥球。
- 未来只有在容量、团队所有权或故障隔离证据充分时拆服务。

## Alternatives

- 全微服务：当前收益不足以覆盖复杂度。
- 单进程包含所有任务：OCR/解析可阻塞在线请求，故拒绝。
- Python 为主后端：不符合本次 Java 商业项目学习目标。
