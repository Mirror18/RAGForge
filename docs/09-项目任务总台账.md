# RAGForge 项目任务总台账

本文件是 RAGForge 唯一的任务看板。它只回答“任务编号是什么、要完成什么、依赖什么、当前是否可以做”，不记录实施日志、测试输出、改动文件清单或阶段复盘。任务完成细节以对应 Git commit 为唯一追溯来源。

## 1. 使用规则

开工前必须从本表选择一个任务，确认依赖、状态和当前工作树，再按仓库 `AGENTS.md` 创建分支、worktree 和 Worker Ticket。一个执行者同时只能有一个 `IN_PROGRESS` 任务。

状态固定为：

| 状态 | 含义 |
|---|---|
| `TODO` | 已规划，依赖满足后可以开始 |
| `IN_PROGRESS` | 已分派并正在实施 |
| `BLOCKED` | 有明确外部阻塞，备注必须写解除条件 |
| `DONE` | 任务目标已完成，真实验证和提交已写入 Git history |
| `CANCELLED` | 不再按原任务实施，备注说明替代任务或原因 |

任务状态不是代码目录的推测结果。`DONE` 必须有对应提交；详细完成内容使用：

```powershell
git log --all --oneline --grep="<任务ID>"
git show --format=fuller <commit-sha>
```

| M0 工程治理 | 建立仓库入口、文档边界、Agent 协作和架构决策 |
| M1 产品闭环 | 完成空间、来源、摄取、索引、检索、问答和管理能力 |
| M2 质量交付 | 建立跨平台回归、契约覆盖、Web 自动化、评估和供应链门禁 |
| M3 部署发布 | 完成容器、Ubuntu 部署、观测、升级回滚和公开化准备 |
| M4 架构演进 | 在现有代码事实基础上实施已接受的架构演进提案 |

## 4. 维护要求

- 新任务使用下一个未占用编号；不要用“阶段1/阶段2”另建任务记录。
- 任务表只写目标、依赖、状态和简短边界；不追加运行日志和测试流水账。
- 状态变化由 Orchestrator 更新；当前下一项只在状态卡中做快照，任务定义仍以本表为准。
- 每个完成任务必须有中文 Conventional Commit；提交正文按 [任务提交信息模板](./14-任务提交信息模板.md) 记录真实完成内容、影响范围、验证、风险和下一步。
- 需要查阅某项任务的实际过程时，使用 `git log --all --oneline --grep="<任务ID>"`，不要寻找已删除的阶段文档。
