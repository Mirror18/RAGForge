# RAGForge 文档索引

本目录按 `dataH` 的方式组织：主题文档负责说明项目本身，治理文档负责当前状态和任务入口，Git commit 负责每次任务的真实执行记录。这里不保存阶段执行日志，也不把完成细节复制成多份记录。

## 3. Git history：任务执行的唯一详细记录

需要知道某个任务实际完成了什么、改了哪些文件、运行了什么命令、测试结果如何、有哪些风险和回滚方式时，使用：

```powershell
git log --all --oneline --grep="<任务ID或关键词>"
git show --format=fuller <commit-sha>
git show --stat <commit-sha>
```

历史阶段文档如果已从工作树移除，并不代表历史丢失；Git 仍保留原始提交和文件版本。当前文档只保留稳定结论、可执行任务入口和必要的治理状态。

## 4. 根目录边界

- `pom.xml` 留在根目录：Maven 多模块 reactor 的构建入口。
- `CHANGELOG.md` 留在根目录：发布历史，按 Keep a Changelog 维护。
- `AGENTS.md` 留在根目录：仓库协作硬规则。
- `README.md` 留在根目录：项目入口和最短导航。
- `.github/` 保存 GitHub 标准贡献和安全入口；`.agents/tickets/` 保存机器可读 Worker 合同；`tests/evidence/` 保存结构化验证结果。

## 5. 文档维护规则

- 稳定说明写主题文档；任务编号和目标写 `09`；当前阻塞写 `08`。
- 产品范围变化同步架构/功能/风险/追溯文档；架构变化必须先有 ADR。
- 真实任务执行细节写 Git commit body，不在 docs 追加日志。
- 文档引用使用相对 Markdown 链接；外部资料使用直接 HTTPS 链接。
